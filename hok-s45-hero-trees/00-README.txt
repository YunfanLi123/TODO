一、这套文档是什么
════════════════════════════════════════════════════════════════════

五条分路各一份纯文本决策树，覆盖 147 名英雄的**前 / 中 / 后三期动作模式**。

结构沿用《分路决策树》（工作区 honor-of-kings-s45-lane-decision-tree.txt）的那一套：
时间轴分叉，每个分支写「前提 / 动作 / 后果」，后果末尾的【状态标签】带到下一节点。

与分路级文档的关系：
  分路级文档（既有）回答「这个位置在做什么」
  本套英雄级文档回答「换成这个英雄，在同一时间节点具体做什么」

全局前提（时间轴、版本改动、视野机制）在五份文件的头部各自写了一遍，
此处只列一份汇总，见第三节。

版本环境结论（五份文件的共同前提）
  1  S45 官方公告中不存在兵线规则、野怪刷新、中立资源刷新、防御塔保护机制的改动。
     资源分配层未动，中野辅三人在前期的资源总量仍高于两条边路与发育路。
     边路与发育路的前中期产出是把个人线权转成团队资源，而不是打爆对手。
  2  坦装集体回暖，中期团战性质从「冲脸打穿前排」转向「找后排 + 打控制窗口」。
  3  视野精灵巡逻化 + 视野规则四条，压缩了草丛与绕后的信息收益，
     「没看到人」不再等于「这里没人」。
  4  雾行千山让跨地形脱战与进场成为常规操作，野区的墙不再等同于安全边界。
  5  中路是 S45 改动最少的位置（前 8 分钟话语权高于打野）；
     对抗路与发育路的资源被中野辅挤压，打野的抓人成本被防御塔免伤与空间之灵抬高。

四、怎么读
════════════════════════════════════════════════════════════════════

单个英雄块的读法
  英雄名
    定位与关键数据    梯队标注 + 官方数据（标注口径）+ S45 是否被改动
    机制要点          该英雄在 S45 的机制变化与关键操作
  0:00 节点
  ├─ 前提：<当场能看到的地图事实>
  │  动作：<具体做什么>
  │  动作：<具体做什么>
  │  后果：<结果>，状态【标签】
  ├─ 前提：<条件>
  │  动作：<具体做什么>
  │  后果：<结果>，状态【标签】
  └─ 前提：<条件>
     ├─ 前提：<子条件>
     │  动作：<具体做什么>
     │  后果：<结果>，状态【标签】
     └─ 前提：<子条件>
        动作：<具体做什么>
        后果：<结果>，状态【标签】

读法约定
  · 「前提」只写当场可观测的地图事实：敌方头像在小地图的位置、塔是否已破、谁阵亡、
    技能是否已交、兵线位置、视野是否存在、倒计时。不写经济差、等级差、评分、局势优劣。
  · 「动作」只写该英雄技能能做到的具体操作。
  · 「后果」末尾的【状态标签】是下一节点的前提输入，构成状态链。
  · 缩进两空格；分隔线为一整行等号；纯文本，无标记语法；UTF-8 无 BOM，LF 行尾。

用法
  · 练某个英雄：直接翻到该英雄块，从 0:00 节点顺读，每个分支的前提都是可自查的状态。
  · 对局复盘：回看自己死的那个时间点，看该英雄在同类前提下的分支动作与后果。
  · 阵容讨论：看同一位置的多个英雄在同一前提下的不同动作，选容错更高的那个。

六、校验
════════════════════════════════════════════════════════════════════

复核脚本  verify-all-lanes.py（可重复运行）
  python "<本机目录>"
  输出  verify-all-lanes.txt
  最近一次结果：五份文件全部通过，合计 698948 字节 / 349.5 页 / 147 英雄 / 882 节点 / 2910 分支

检查项
  字节数与页数
  每份文件的英雄名单是否全覆盖、有无重复
  节点数是否等于英雄数 × 6、六个节点的顺序是否正确
  每条分支是否同时含 前提 / 动作 / 后果
  每条后果末尾是否带【状态标签】、被引用的标签是否都已定义
  每个节点的下一节点前提是否引用了上一节点产出的标签（状态链）
  是否残留 ASCII markdown 符号
  是否残留主观评价词（最强、必选、版本答案、碾压、无脑、划算等）
  是否残留不可观测前提（劣势、领先、经济差、等级差、评分、局势、占优、逆风、顺风、崩盘）

同目录另有各分路 worker 留下的校验与规范化脚本
  normalize_tree.py         合并分块 + 统一树形缩进 + 硬性验收
  normalize_clash_tree.py   对抗路前缀归一
  verify-trees.ps1          结构验收
  verify-roam-trees.py      游走位合并与验收
  这些脚本只影响对应文件，重复运行前先看内容。
