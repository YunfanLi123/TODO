# 复盘：从「传统 CV 解析王者录屏」到「接大模型」的转向

> 用户判语：**「现在宣布目前所有的尝试失败。」**
> 本文记录**我们试过什么、为什么不行、学到了什么**，
> 以及新方向要避开哪些坑。

---

## 0. 结论先行

**失败的不是某几个算法，是整条路线的假设。**

我们一直假设「王者复盘 = 从画面里读出几个数（位置、经济差、击杀数、动作），
再拿这些数去对规则库」。这个假设有三个致命处：

| 假设 | 现实 | 后果 |
| --- | --- | --- |
| 画面里有足够的事实 | 王者顶栏**不显示经济**；击杀数模板 17 个已知时刻只读对 2 个；补刀/开团没有现成检测器 | 规则引用的 1680 条里，只有 **28%** 的条件能被满足 |
| 动作可以从低层信号反推 | 「刷野 / 转线 / 带线」是**语义**，在轨迹上是连续量，没有阈值能判「像不像」 | 探测器只能给弱信号 → 结论既不可信也没用 |
| 规则命中就是产品价值 | 玩家真正想知道的是「这一波我该怎么打才更好」 | 报告回答的是「你违反了 4 条规则」，不是「你该怎么做」 |

**新方向**：让**视觉语言模型直接看视频**，产出**语义**（这一波在干什么、错在哪），
再与**可迭代的操作模式库**匹配；报告只给「**改了就一定变好**」的建议，并附上对应片段。

---

## 1. 试过的每一条路（含实测数字）

### 1.1 按灰度差切「回合」 —— ❌ 前提就错

- 实测：一局王者切出 **80 个「回合」**，但真正值得判断的时刻不到 30 个。
- 原因：王者是**连续的一整场**，灰度差触发的是镜头移动与技能特效，与「操作模式的时间窗」毫无关系。
- 教训：**没有回合这种东西**，别把自走棋的切法搬过来。

### 1.2 读时钟（OCR 模板匹配计时器） —— ✅ 唯一真正成功的技术

- 实测：573 个采样**全部读出**，斜率 **1.0002**，残差 **±2.1 秒**，对局起点误差 0.8 秒。
- 限制：只能给「局内第几分钟」，给不了「做了什么」。
- 教训：**时间轴是这类产品的前提，值得单独做**。新方案里它仍然有用（给模型提供时间锚点）。

### 1.3 顶栏数字（经济差 / 击杀差） —— ❌ 一个恒缺、一个不可用

- `gold_diff`：**王者顶栏默认不显示经济** → 恒为缺失（**不是 0**）。
- `kill_diff`：机制齐了（区域/颜色/切分/聚类/标号工具都在），但模板**没验收**（2/17）→ 宁可不启用。
- 教训：**规则引用了读不出的事实，就等于那条规则永远不触发**，而报告上只是「没结论」。

### 1.4 小地图绿点当玩家位置 —— ❌ 被实测证伪

- 一度把绿色标记当「玩家自己的位置」（王者会给自己的头像加绿圈）。
- 实测：绿点是**队友标记**；玩家自己**没有**标记。
- 后果：英雄位置追踪覆盖率只有 **63%**，缺口是阵亡期与遮挡。
- 教训：**没有先验就去猜画面语义，猜错会一路错下去**，而且是在没人看得出错的地方。

### 1.5 龙坑图标认「拿龙」 —— ⚠️ 颜色不可靠，改用固定位置

- 同一坑位 t=175 紫粉、t=600 金白 → 颜色会随状态变，**不能**用来认哪个是主宰。
- 改用**固定位置**（蓝方视角主宰坑左上、暴君坑右下）。
- 教训：王者会**中心反转 180°**（官方作战指南），区域表必须按阵营相对存。

### 1.6 区域表（泉水/野区/河道/三条路 + 阵营相对） —— ✅ 做成了，但不够

- 蓝方/红方两套框，视角分不出时**不判**；框用实测轨迹热力图标定。
- 只能回答「**他在哪**」，回答不了「**他在干什么**」。

### 1.7 证据探测器（三态 found / absent / unknown） —— ⚠️ 机制对，覆盖率不够

- 机制是对的：只有**强探测器**才能判 `absent`（明确没做）；`unknown` 一律判「无法判定」。
- 但覆盖的只是**有干净信号**的那几类：开大龙团、回城、占位。
- 刷野 / 转线 / 带线这类**弱信号**在轨迹上是连续量，阈值是编的。
- 成果：规则库 1680 条里，**470 条（28%）** 全可判，加弱信号 877 条（52%）。
- 端到端实测（用例2，玩家零标注）：可判定 4 条、无法判定 2 条、结论 4 条。
  → **这就是「诚实但没用」的典型**：没编造，但也没帮上忙。

### 1.8 逐段标注页 —— ❌ 玩家直接否掉

- 玩家原话：**「我完全不想标」**、**「把逐段标注这个功能去掉吧」**。
- 一局 25 个动作选项 × 6 段 = 150 次点击，而这些**画面里就能看出来**。
- 改成**只读展示**「系统看到 / 画面里没看到 / 读不出来 / 依据」。
- 教训：**让人干模型的活，是产品设计失败**。识别层做不到的，才该问人。

### 1.9 对局起点校正 —— ⚠️ 一度做错，被用户点破

- 原做法：前端把每段的时间**平移**一下。
- 用户判语：**「肯定不能推算啊」**。
- 原因：起点偏了多少，原来那批帧显示的局内时刻就偏了多少 —— 平移旧结论 = **拿错时刻的画面去说那一段的事**，方向全对、证据对不上。
- 改法：服务端按新起点**重新抽帧、重新识别**（`app/collection/realign.py`）。
- 教训：**改一个输入就要重算依赖它的东西**，不能只挪数字。

### 1.10 界面上的几处硬伤（用户逐条点名）

| 问题 | 根因 | 现状 |
| --- | --- | --- |
| 进度条与「上传并扫描」压在梦琪脸上 | 角色绝对定位铺满整卡，按钮与进度条是整行宽度 | 改成 grid **两列**：控件一列、角色一列（结构上压不上） |
| 完成时那张脸很凶 | 「两道向上弯的弧」长在眼睛位置 = **怒眉**，深色嘴腔 = 在吼 | 圆眼睛照旧睁着 + 玫瑰色笑口（有舌头） |
| 页面上摆 `hok-video-69481d223ed9` | 内部 id 是机器认的东西 | 显示**视频原始文件名 · 分路 · 胜负** |
| 「从 (0.05,0.96) 到 (0.14,0.18)」 | 归一化坐标是给算法看的 | 换成区域名（「从泉水走到对抗路」） |
| BP 录入要一环一环自己选 | 复盘全靠人填 | 新方向：模型读出来，**人来核对** |

## 2. 经验与教训（这才是要带走的东西）

1. **判定层的上限 = 识别层能提供的信号的交集。**
   我们花了很久才接受这件事：规则库 1680 条、判定内核做得再干净，
   只要识别层给不出经济差/击杀差/补刀/开团，能判的就只有 28%。
   **先算交集，再写内核。**

2. **低层信号撑不起语义判断。**
   几何、颜色、模板、OCR 能回答「他在哪、几点、大招好没好」，
   回答不了「这一波该怎么打」。**王者复盘是语义任务。**

3. **弱信号没有阈值。**
   「刷野像不像」「转线像不像」在轨迹上是连续量。
   用阈值去判，等于**编造**——而且编得很像真的。
   这类判断只能交给能理解画面的模型，或者干脆不判。

4. **「如实说读不出来」是底线，不是产品。**
   我们把「无法判定」做得很干净（不猜、不用 0 冒充），这是对的；
   但一份只有「无法判定」的报告没有价值。
   **诚实要配上「至少有一件事是真有用的」。**

5. **规则命中 ≠ 产品价值。**
   「你违反了 4 条规则」不是玩家要的东西。玩家要的是：
   **「这一波你该先开龙再带线，改了这一点你就能赢」**。

6. **先验必须被证伪过才能用。**
   小地图绿点那次：没有先验就猜，猜错了还在没人看得出错的地方一路错下去。

7. **不要用「命中规则」当目标指标。**
   覆盖率 28%、触发 6 条、判定 4 条 —— 这些数字好看，但用户不在乎。
   要盯的是：**这份报告让他下一次真的会改**。

8. **数据许可是硬约束。**
   唯一公开的王者检测数据集**禁止商业使用** → 不能依赖公开数据集训练或商用。
   调研新方案时，许可证一栏必须逐条写清。

9. **每一层都要能被单独测。**
   好处：这次转向时，**内核、模式库、报告骨架、录制上传链路、时钟读取都能留下**，
   只有「识别」那一层要换掉。**架构上把可换的部分隔出来，掉头才不痛。**

## 3. 新方向的产品原则（用户定的）

1. **接大模型看视频**，产出语义，与操作模式库匹配。
2. **模式库不再死板**：可调、可迭代（用户明确提到按 GitHub 调整），
   让它能灵活指导玩家对局的状态，而不是一张死表。
3. **不吹毛求疵**：不要挑玩家视频里的芝麻小事。
   只指出「**百分百改正后就能提升**」的地方。
4. **仍然要截取对应段落视频**：建议必须能回看原画面。

## 4. 转向后哪些资产留下（不白做）

| 资产 | 状态 | 在新方案里的位置 |
| --- | --- | --- |
| 操作模式库 1680 条 + 溯源原文 | ✅ 保留，但要能改 | 匹配用的知识底座；从「死表」改成「可迭代」 |
| 判定内核（规则匹配/归因/分路收拢） | ✅ 保留 | 模型产出结构化事实后，仍然由内核判「对/错/不适用」 |
| 报告骨架（四部分结构、证据时刻、片段定位） | ✅ 保留 | 建议的排版与视频片段定位 |
| 上传/录制/抽帧/时钟读取链路 | ✅ 保留 | 给模型准备素材与时间锚点 |
| 小地图/区域表/键位档位 | ✅ 保留 | 作为**可选的辅助信号**喂给模型（不再是唯一依据） |
| **传统 CV 探测器** | ❌ 降级 | 变成「模型读不准时的兜底」，不再当主判据 |
| 逐段标注 | ❌ 删除 | 模型直接读；玩家只核对 |
