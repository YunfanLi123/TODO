# BYG 开发与演化支持文档

> 线上版 `byg/`（2026-11-24）｜读者：接手开发者

## 一、数据全景

**数据源**：对局录屏（访客上传）；攻略与操作模式（`app/seed/sources/`、`mode-library/`）；英雄/分路/技能模式库（`app/seed/hok_*.json`，由 `tools/build_*.py` 生成）；视觉大模型（访客在 `/model` 填自己的 Key，按设备隔离）；规则审核痕迹。

**加工**：视频→抽帧→分时段/分路→VLM 识别→payload；攻略→规则 DSL→准入校验→模式库 JSON；payload+模式库→匹配/归因→判定（满足/违背/未判定/触发，读不出记「未判定」）；模式库分块+向量→Qdrant→「问 AI」局外拓展；报告层出中文复盘与导出。

**存储**：对局/分析/规则在容器内 SQLite `/data/app.db`；视频在 `/data/videos/<设备>/`；模式库 `mode_library.db`、向量 `<数据目录>/qdrant/`（可再生）；访客 Key 存 `devices/<设备>/config.yaml`。整体**热数据即焚**。

**数据流**：填 Key→上传→识别→落 matches→规则匹配→落 analyses→出报告→关页 30 秒后按 `player_id` 清扫，1 小时无动静回收。

**数据潭**：目前没有——公共部署刻意不留数据。规划：热层 SQLite（即焚）→ PG（已建表建策略，差连接串）→ 数据潭做长期归档与跨局成长曲线。

## 二、怎么改错

1. 先复现再改；`tools/` 有 120+ 个 `verify_*`/`probe_*`/`diag_*` 诊断脚本，别造轮子。
2. **一份定义只能有一处来源**。已踩坑：RLS 策略两处各抄一份，改一处漏一处→建策略崩→一个都没建。现在策略 SQL 只有 `app.db_rls.rls_statements()`。
3. 按「用户实际看到的样子」验证（`tools/check_md_hazards.py` 等是自动化版），只跑相关测试不跑全量。
4. 改数据层必须复查隔离：应用层按 `player_id` 过滤是第一道防线，行级安全是第二道。

## 三、怎么增减功能

**加**：新模式 → 改 `tools/build_hok_*.py` 源数据→重跑生成 `app/seed/*.json`→灌库，**不要手改 JSON**（那是生成产物）。新游戏 → `app/adapters/` 加 adapter 实现 `base.py` 并在 `registry.py` 注册，核心链路不动。新页面/接口 → 路由 `app/main.py`、模板 `app/templates/`、样式 `app/static/`（模板是数据文件，拷进去即生效）。

**减**：下线规则/游戏 → 改 `status` 并隐藏入口，**不删数据**（「删掉」默认是「不展示」）。真删行 → 走 `app/core/session.py` 的按设备删除逻辑，别写裸 `DELETE`。整功能下线 → 留代码不挂路由；规则按 `(game, version)` 分区，可并存两套对比、回退切版本号。

**底线**：① 不预置 API Key（环境变量里的 Key 全站共享），访客自带；② 不预判画面，读不出记「未判定」；③ 改完按用户看到的样子验一遍再报完成。
